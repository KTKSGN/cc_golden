# Эталон VM для Claude Code: как это устроено

Документ для того, кто вернулся к проекту спустя время и хочет быстро понять, что это, как работает и что делать. Краткая инструкция по установке есть в `README.md`, здесь подробности и обоснования.

## 1. Зачем это

Нужна виртуальная машина, где Claude Code работает **круглосуточно под отдельным непривилегированным пользователем** и доступен владельцу с телефона или компьютера через Remote Control (приложение Claude, вкладка Code). Машину нужно уметь **воспроизвести с нуля одним файлом**, без чьей-либо памяти и без истории чатов.

Решение: один файл `bootstrap.sh`. Он автономный (установщик и все файлы внутри), ничего не спрашивает, каждую изменяющую команду печатает до выполнения и безопасен при повторном запуске.

## 2. Устройство

```
bootstrap.sh                 установщик + встроенный архив файлов infra/
infra/                       исходники (из них bootstrap.sh собирается)
  install.sh                   логика установки
  build.sh                     сборка bootstrap.sh и проверка --check
  CLAUDE.md                    правила агента → /etc/claude-code/CLAUDE.md
  systemd/                     служба агента, обновление Claude Code
  bin/                         скрипты агента
  templates/                   пустые шаблоны памяти (только заголовки)
docs/PROJECT.md              этот документ
```

Что оказывается на машине:

| Путь | Что | Владелец |
|---|---|---|
| `/etc/claude-code/CLAUDE.md` | правила агента (права, граница, порядок работы) | root |
| `/etc/systemd/system/claude-agent.service` и `.d/{resume,wait-dns,workdir}.conf` | служба: Claude Code с Remote Control в tmux-сессии `claude` | root |
| `/etc/systemd/system/claude-code-update.{service,timer}` | раз в неделю обновляет только пакет `claude-code` | root |
| `/opt/claude-golden/infra/` | копия эталона (шаблоны, справка), агент только читает | root |
| `~claude/.local/bin/` | `claude-agent-start`, `claude-rc`, `claude-connect-memory`, `claude-watch-exchange` | claude |
| `/home/claude/github/` | рабочая папка агента (см. ниже) | claude |

Рабочая папка агента:

```
/home/claude/github/
├── infra/    ссылка на /opt/claude-golden/infra (только чтение)
├── memory/   клон приватного репозитория памяти (подключается отдельно)
└── source/   репозитории владельца
```

## 3. Что делает установщик (по шагам)

1. **Проверки:** root, Debian 13, все файлы на месте.
2. **Пользователь `claude`:** без пароля, без `sudo`; папка `/home/claude/github`. Сразу после создания проверяется, что `claude` **не может менять сам установщик** (иначе он получил бы root).
3. **Пакеты:** `sudo curl git gnupg tmux auditd qemu-guest-agent podman uidmap passt openssh-client`.
4. **Claude Code** из apt-репозитория Anthropic (канал stable). Ключ репозитория сверяется с отпечатком `31DDDE24DDFAB679F42D7BD2BAA929FF1A7ECACE`, при несовпадении установка останавливается.
5. **Правила агента** в `/etc/claude-code/CLAUDE.md`.
6. **Служба, таймер обновления, скрипты.**
7. **Копия эталона** в `/opt/claude-golden`, рабочая папка: `source/` и ссылка `infra`.
8. **Включение** auditd, таймера обновления, службы агента.
9. **Самопроверка** с отчётом PASS / FAIL.
10. Блоки «Как этот экземпляр будет выглядеть у вас» и «СДЕЛАЙТЕ РУКАМИ».

Принципы работы установщика:
- **Прозрачность.** Каждая команда, меняющая систему, печатается строкой `+ …` до выполнения. `--dry-run` только печатает.
- **Идемпотентность.** Совпадающие файлы пропускаются. Если файл на машине отличается, показывается diff и спрашивается «да/нет»; при «да» старый сохраняется как `<файл>.bak-<дата>`. Предыдущая копия эталона остаётся как `/opt/claude-golden.prev`.
- **Не трогает:** `source/`, `memory/`, вход в Claude. Работающую службу не перезапускает (перезапуск оборвал бы сессию): только подсказывает команду.
- **Сеть не настраивает и не проверяет.** Адрес, DNS и выход в интернет должны уже работать.

## 4. Как устроен `bootstrap.sh`

Это `infra/install.sh`, за ним строка `exit 0`, метка `__INFRA_PAYLOAD__` и архив остальных файлов `infra/` (tar.gz в base64). При запуске установщик находит метку в себе и распаковывает архив во временную папку. Архив это только данные, bash дальше `exit 0` не читает. Поэтому **файл можно скачать, перенести флешкой или `scp`**, ничего больше не нужно.

Сборка воспроизводимая (порядок, даты и права в архиве фиксированы):

```
infra/build.sh            # пересобрать bootstrap.sh
infra/build.sh --check    # убедиться, что bootstrap.sh совпадает с infra/
```

После **любой** правки в `infra/` пересоберите и закоммитьте `bootstrap.sh` вместе с правкой.

## 5. Установка, обновление, проверка

На новой VM под обычным пользователем (в минимальном Debian нет `curl`, `sudo` ставит инсталлятор Debian при пустом пароле root):

```
sudo apt-get update && sudo apt-get install -y curl
curl -fsSLO https://raw.githubusercontent.com/ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ/main/bootstrap.sh
sha256sum bootstrap.sh
sudo bash bootstrap.sh --dry-run
sudo bash bootstrap.sh
```

- `ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ` — адрес этого репозитория на GitHub. Можно и без `curl`: скачать `bootstrap.sh` со страницы репозитория (Download raw file) и перенести флешкой или `scp`.
- Запускайте через `bash`, а не `./`: бит исполнения теряется при скачивании zip и копировании без `-p`.
- Файл кладите **не в `/home/claude`**, а туда, где пишете только вы или root: установщик в противном случае остановится.
- Если при установке Debian был задан пароль root, `sudo` не будет: зайдите в root командой **`su -`** (с дефисом; без него в `PATH` нет `/usr/sbin`) и запустите `bash bootstrap.sh`. Свою учётную запись в группу `sudo` добавьте сами: `usermod -aG sudo ПОЛЬЗОВАТЕЛЬ`.
- **Обновление:** новая версия `bootstrap.sh` и тот же запуск.
- **Откат:** старые файлы лежат рядом как `.bak-<дата>`, прежняя копия эталона `/opt/claude-golden.prev`; надёжнее всего снапшот VM до установки.

### Руками после установки

1. `sudo -u claude tmux attach -t claude` — выбрать тему, войти в аккаунт по ссылке, подтвердить доверие к папке. Выйти: Ctrl+B, затем D (**не** Ctrl+C и не exit).
2. `sudo reboot`; после загрузки `systemctl is-active claude-agent.service` → `active`, в приложении появилась сессия `claude-<имя VM>`.
3. Подключить память (см. раздел 6).
4. **Изолировать VM от локальной сети на роутере** (отдельная VLAN или правило «только интернет»): агенту видно всё, что видно машине.

### Имя экземпляра

Имя сессии в приложении `claude-<имя хоста>` (без домена), папка памяти `memory/hosts/<имя хоста>/`. Своё имя задайте **до подключения памяти**: `sudo hostnamectl set-hostname ИМЯ && sudo systemctl restart claude-agent.service` (перезапуск оборвёт сессию).

### Проверка «всё ли хорошо»

Вставьте на VM под обычным пользователем, блок только читает. На здоровой машине после перезагрузки: `ок 25, проблем 0`.

```bash
sudo bash -s <<'EOF'
p=0; f=0
chk() { local d=$1; shift; if "$@" </dev/null >/dev/null 2>&1; then printf '[ OK ] %s\n' "$d"; p=$((p+1)); else printf '[FAIL] %s\n' "$d"; f=$((f+1)); fi; }
. /etc/os-release
echo "Система: $PRETTY_NAME, ядро $(uname -r), хост $(uname -n)"
chk "Debian 13" test "$VERSION_ID" = 13
chk "пользователь claude есть" id claude
chk "пароль claude заблокирован" bash -c "passwd -S claude | awk '{exit \$2!=\"L\"}'"
chk "claude НЕ в группе sudo" bash -c "! id -nG claude | tr ' ' '\n' | grep -qx sudo"
chk "claude-code установлен" dpkg -s claude-code
chk "claude запускается" runuser -u claude -- claude --version
for pkg in tmux auditd podman git curl openssh-client; do chk "пакет $pkg" dpkg -s "$pkg"; done
chk "claude-agent.service включён" systemctl is-enabled claude-agent.service
chk "claude-agent.service работает" systemctl is-active claude-agent.service
chk "таймер обновления Claude Code включён" systemctl is-enabled claude-code-update.timer
chk "auditd работает" systemctl is-active auditd
chk "tmux-сессия claude есть" runuser -u claude -- tmux has-session -t claude
chk "правила /etc/claude-code/CLAUDE.md на месте" test -s /etc/claude-code/CLAUDE.md
chk "эталон /opt/claude-golden принадлежит root" test "$(stat -c %U /opt/claude-golden)" = root
chk "агент НЕ может писать в эталон" bash -c "! runuser -u claude -- test -w /opt/claude-golden/infra"
chk "рабочая папка: source/ и ссылка infra" bash -c "test -d /home/claude/github/source && test \"\$(readlink /home/claude/github/infra)\" = /opt/claude-golden/infra"
chk "скрипты агента в ~claude/.local/bin" bash -c "for s in claude-agent-start claude-rc claude-connect-memory claude-watch-exchange; do test -x /home/claude/.local/bin/\$s || exit 1; done"
chk "subuid/subgid для podman" bash -c "grep -q '^claude:' /etc/subuid && grep -q '^claude:' /etc/subgid"
chk "DNS: api.anthropic.com резолвится" getent hosts api.anthropic.com
chk "auditd пишет события claude" bash -c "ausearch -ul \$(id -u claude) -ts today"
echo; echo "Итого: ок $p, проблем $f"
echo "--- последние строки службы:"
journalctl -u claude-agent.service -b --no-pager -n 12 2>&1 | cut -c1-160
EOF
```

## 6. Память и обмен задачами

Память это **приватный** репозиторий GitHub, который клонируется в `~/github/memory`. Подключение:

```
sudo -u claude -i claude-connect-memory git@github.com:ВЛАДЕЛЕЦ/РЕПО.git
```

Скрипт: спрашивает имя и email для git (лучше не личная почта), создаёт ключ `~/.ssh/github_memory` и алиас `github-memory`, сверяет отпечаток github.com, показывает ключ и ждёт, пока вы добавите его как **deploy key с правом записи** (Settings → Deploy keys), клонирует, при пустом репозитории кладёт шаблоны и создаёт `hosts/<имя VM>/`. Повторный запуск безопасен.

Раскладка памяти, чтобы **одну память делили несколько VM**:

```
README.md                  протокол (из infra/templates/memory/)
notes/                     общее для всех VM
hosts/<имя VM>/
  JOURNAL.md               журнал: что сделано, когда и зачем (новые записи сверху)
  exchange/
    from-claude.md         задачи от чата для агента этой VM (пометка «from Cloud»)
    from-claude-code.md    ответы агента (пометка «from Cloud Code»)
```

Агент пишет только в свою папку `hosts/<имя>/` и в `notes/`. Чат (Claude в приложении или на claude.ai) пишет задачи в `from-claude.md` и читает ответы. Сообщать чату путь не нужно: `README.md` в корне памяти начинается с раздела «Для Claude из чата», где описано, куда писать и как выбрать машину. Записи не удаляются и не правятся задним числом; ответ на задачу начинается с `[сделано]` или `[не сделано]`.

### Таймер задач

`claude-watch-exchange` ждёт новую запись `*from-claude.md`. Это обычный `git ls-remote` без участия модели, поэтому **токены не тратятся**; агент просыпается только когда задача появилась. Темп: раз в 3 минуты, пока идёт работа; раз в 5 после 15 минут тишины; через 30 минут без сообщений владельца и без коммитов на GitHub таймер сам выключается. Нашёл задачу — агент сообщает владельцу и **ничего не выполняет без его слова**. Запускается агентом в начале активной работы; в консоли Claude Code он виден как одна фоновая задача.

## 7. Модель безопасности

- Агент работает как `claude`: **без `sudo`, без пароля**, не в привилегированных группах. Все его действия попадают в auditd под `auid=claude` (служба открывает полноценную PAM-сессию).
- Код, который выполняется от root (`bootstrap.sh`), агент менять не может: установщик это проверяет и отказывается запускаться из места, доступного агенту на запись. Копия эталона и правила агента принадлежат root.
- Правила агента (`/etc/claude-code/CLAUDE.md`) запрещают просить права, обходить ограничения, публиковать наружу и совершать необратимые действия без подтверждения владельца; так же только с подтверждения — вызовы внешних API (кроме Anthropic и GitHub-репозиториев владельца), установка пакетов любыми менеджерами, подключение MCP-серверов и загрузка скриптов из интернета; текст из внешних источников считается данными, а не инструкциями.
- Сеть: установщик её **не** изолирует. Изоляция снаружи (VLAN / роутер) — задача владельца.
- Ключи Anthropic и github.com сверяются с отпечатками; приватные ключи генерируются на месте и никуда не выводятся.
- В репозитории эталона нет секретов, ключей, паролей, внутренних адресов.

## 8. Как менять эталон

1. Правки только в ветку `dev`; в `main` попадает то, что владелец посмотрел: `bootstrap.sh` из `main` исполняется от root на каждой машине.
2. После правки `infra/` — `infra/build.sh`, затем `infra/build.sh --check`.
3. Проверки перед пушем: shellcheck (`infra/install.sh`, `infra/build.sh`, `infra/bin/*`), прогон в чистом контейнере `debian:trixie` в rootless podman (установка из одного файла, повторный запуск без изменений, обновление, защита, `--dry-run`), поиск следов и секретов в файлах и в содержимом архива.
4. Контейнеры не имеют systemd и auditd: проверки службы и auditd возможны только на настоящей VM.

## 9. Что проверено

На настоящей VM (чистый Debian 13, установка из `main`): служба включена и работает, tmux-сессия есть, auditd пишет события `claude`, таймер обновления включён, защита и раскладка `/opt` работают; блок проверки выдал `ок 25, проблем 0`. Таймер задач на настоящем GitHub замечает коммиты.

В контейнерах: установка одним файлом, повторный запуск (ноль изменений), обновление новой версией, защита от запуска из папки агента, повреждённый файл, подключение памяти к пустому репозиторию и две VM на одной памяти.

**Не проверено:** вход в Claude и отображение сессии в приложении под именем `claude-<имя VM>`; поведение после перезагрузки; подключение памяти по SSH к настоящему GitHub (скрипт проверен на локальном репозитории); работа таймера задач на репозитории памяти.

## 10. Частые проблемы

| Симптом | Причина и что делать |
|---|---|
| `Permission denied` при `./install.sh` | потерян бит исполнения; запускайте `bash …` |
| `useradd: command not found` | запустили через `su` без дефиса; нужен `su -` |
| `sudo: command not found` | при установке Debian задан пароль root; см. раздел 5 |
| «доступен на запись пользователю claude» | файл лежит в `/home/claude` или в доступной ему папке; перенесите |
| `/home/claude принадлежит …` | папка существовала до установки с другим владельцем; проверьте и `chown claude:claude /home/claude` |
| `FAIL auditd` / служба в контейнере | в контейнере нет systemd; ожидаемо |
| после смены имени хоста сессия называется по-старому | перезапустите службу (оборвёт сессию) |
| проверка: `claude-agent.service работает` — FAIL | `journalctl -u claude-agent.service -b`; чаще всего ещё не выполнен первый вход |

## 11. Ограничения

- Только Debian 13 (проверка в установщике).
- Нет команды удаления: откат через `.bak-*`, `/opt/claude-golden.prev` и снапшот VM.
- Установщик не перезапускает работающую службу: новые файлы службы вступят в силу после перезапуска или перезагрузки.
- Вход в аккаунт Claude делается руками и в образ не попадает.
