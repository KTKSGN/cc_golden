# Память Claude

Приватный репозиторий: контекст, журнал и обмен задачами для Claude Code на VM владельца и для Claude в чате. Подключается на VM в `/home/claude/github/memory` командой `claude-connect-memory`.

## Для Claude из чата: прочитай первым

Ты работаешь с этим репозиторием через коннектор GitHub. Обмен с агентами на VM устроен так:

1. Каждая машина — папка в `hosts/`. Имя папки = имя VM; агент на ней — Claude Code, его сессия в приложении называется `claude-<имя VM>`.
2. Задачу агенту пиши в `hosts/<имя VM>/exchange/from-claude.md`: новые записи сверху, пометка `from Cloud`, формат — в разделе «Обмен между чатом и Claude Code» ниже.
3. Ответ агента будет в `hosts/<имя VM>/exchange/from-claude-code.md` (пометка `from Cloud Code`); там же, в `hosts/<имя VM>/JOURNAL.md`, его журнал работ.
4. Если в `hosts/` одна папка — пиши в неё. Если несколько — спроси владельца, для какой машины задача. Если папок нет — память ещё не подключена ни на одной VM: скажи об этом владельцу.
5. Папки `exchange/` в корне репозитория в этой раскладке нет. Если она тебе встретилась — это след старой раскладки, туда не пиши.
6. Агент сам замечает новую задачу, пока владелец с ним работает (таймер задач), иначе — когда владелец попросит. Выполняет её только с согласия владельца.

## Структура

```
README.md                этот файл: правила и протокол
notes/                   общее для всех VM: решения, заметки, итоги обсуждений
hosts/<имя VM>/          одна машина
  JOURNAL.md             журнал: что сделано, когда и зачем (новые записи сверху)
  exchange/
    from-claude.md       задачи от чата для Claude Code этой VM
    from-claude-code.md  ответы Claude Code этой VM
```

Claude Code на VM пишет только в свою папку `hosts/<имя>/` и в `notes/`, чужие `hosts/` не трогает. Так несколько VM не конфликтуют.

## Кто и как сюда подключается

| Кто | Как | Права |
|---|---|---|
| Claude Code на VM (пользователь `claude`) | SSH, deploy key только на этот репозиторий | чтение и запись |
| Чат Claude (приложение, claude.ai) | MCP-коннектор GitHub, токен только на этот репозиторий | чтение и запись по просьбе |
| Владелец | GitHub | всё |

## Обмен между чатом и Claude Code

Два зеркальных файла в `hosts/<имя VM>/exchange/`. Каждый пишет только в свой, чужой только читает.

| Файл | Пишет | Читает | Пометка автора |
|---|---|---|---|
| `from-claude.md` | чат Claude | Claude Code | `from Cloud` |
| `from-claude-code.md` | Claude Code | чат Claude | `from Cloud Code` |

Формат записи — новые сверху:

```
## ГГГГ-ММ-ДД ЧЧ:ММ — тема

from Cloud

Что сделать. Что не трогать.
```

Правила:
- Задача формулируется явно: что сделать и что не трогать.
- Ответ — отдельной записью в своём файле; в первой строке после пометки автора — `[сделано]` (или `[не сделано]` с причиной) и заголовок задачи, на которую отвечаем.
- Записи не удаляются и не правятся задним числом.
- Claude Code не использует sudo/root и не меняет систему; команды для root отдаёт владельцу готовыми.
- Деструктивные и необратимые действия (удаление, перезапись истории, force push, публикация наружу) — только с подтверждения владельца.

Чтение из чата: `get_file_contents` в коннекторе может вернуть `[non-text content: resource]` без текста. Тогда — «Get commit details» с диффом последнего коммита, менявшего нужный файл: новые строки видны в патче с `+`.

## Безопасность

- Секреты (пароли, ключи, токены, серийные номера) и внутренние сетевые адреса сюда не попадают.
- Перед каждым пушем — проверка диффа:
  `git diff --cached | grep -n -i -E "password|passwd|secret|token|api[_-]?key|PRIVATE KEY|BEGIN OPENSSH"`
  Совпадение — стоп и сообщение владельцу.
- Сырые логи сессий Claude (`*.jsonl`) не коммитятся.
