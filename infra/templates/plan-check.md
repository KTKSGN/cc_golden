# Плановая проверка

Запускается по таймеру сессии (CronCreate) или сторожем. Имя хоста `<host>` — вывод `hostname -s`.
Итог первым, без повторов. Токены беречь: читать точечно.

## Порядок

1. `date` — время только с сервера.
2. `git -C ~/github/memory pull --ff-only` — подтянуть память.
3. Искать новое:
   - новые файлы `exchange/TASK-<host>-*` в памяти;
   - `reply-to-<host>.md` (изменён после прошлой проверки);
   - `/home/exchange/results/` — файлы новее файла состояния `~/.local/state/jarvis-plan.state`;
   - упавшие фоновые работы (юниты, таймеры, задания исполнителей).
4. «Новое» = новые или изменённые входящие задачи, ответы или упавшие фоновые работы. Больше ничего.

## Если нового нет

Владельцу НИЧЕГО не писать: ни строки, ни «Нового нет», ни «проверка пройдена».
Только:

1. `jarvis-plan-backoff quiet` — интервал удваивается, команда печатает cron-строку;
2. `CronCreate` с recurring=false, cron-строка из вывода, текст промта плановой проверки.

На этом всё.

## Если новое есть

1. Обработать по правилам проекта.
2. Владельцу — одна-две строки: что пришло и что сделано.
3. `jarvis-plan-backoff news` — интервал возвращается к базе.
4. `CronCreate` (recurring=false) по выданной cron-строке.

«Нового нет» владельцу не писать никогда.

## Служебное

- `jarvis-plan-backoff status` — интервал, счётчик тишины, время следующей проверки.
- `jarvis-plan-backoff reset` — сбросить состояние.
- Настройки: `~/.config/plan-check.conf`.
